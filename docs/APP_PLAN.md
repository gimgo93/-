# 모아: 시민 의견을 정책으로 연결하는 앱

앱 이름은 계획서의 빈 제목을 대신해 정한 임시 이름이다.
요구사항은 사용자가 제공한 「인문사회 융합인재 해커톤 경연 활동 조별 계획서」의
제작 동기와 앱 구성요소에서 추출했다. 문서의 조원 개인정보는 저장소에 옮기지 않았다.

## 만들려는 앱

시민 의견을 많이 모으는 데 그치지 않고, 소수 주민이나 취약계층이 겪는 심각한 문제도
정책 우선순위와 예산 검토에 반영하는 시민 참여 정책 탐구 도구다.

| 계획서 구성요소 | 구현 |
| --- | --- |
| 시민 의견 수집 | 지역·제목·내용·심각성·취약계층 영향 입력, 공개 동의, 독립 D1 저장, 접수 번호 |
| 의견 자동 분류 | 한국어 키워드 규칙으로 분야와 정책 연결, 분류 근거 표시, 시민의 직접 분야 선택 |
| 정책 우선순위 | 심각성 평균·취약계층 영향 평균·빈도 로그 정규화의 가중합, 조절 가능한 가중치, 계산 근거 |
| 예산 배분 시뮬레이션 | 예산·정책별 비용·수혜 가정 편집, 점수·형평성·예산당 수혜 기준의 전액 순차 배분 |
| 시각화와 제안 | 7일 의견 추이, 분야별 비중, 순위표, 예산 비교, 제안서와 CSV·인쇄/PDF |

## 분석 계약

- 심각성과 취약계층 영향은 각각 1~5의 시민 자기보고 점수다. 각각 평균/5×100으로 환산한다.
- 빈도 점수는 `log(1+해당 정책 의견 수)/log(1+현재 필터에서의 최대 의견 수)×100`이다.
- 기본 가중치는 40/40/20이다. 가중치 합으로 정규화하며 합이 0이면 기본값을 사용한다.
- 접수 의견이 없는 정책에는 점수를 만들지 않는다. 동점은 취약계층 영향, 정책 ID 순으로 정렬한다.
- 예산은 선택한 기준의 순서로 정책 비용 전액을 확보할 수 있을 때 배분한다.
  남은 예산보다 비싼 정책은 건너뛰며, 분할 지원이나 수학적 최적해를 주장하지 않는다.
- 수혜 건수는 단순 합계다. 실제 인원이나 정책 사이 중복 제거가 이루어진 숫자가 아니다.
- 최대 최근 500건으로 분석하며 초과 시 화면에 분석 범위를 알린다. 검색과 지역·분야 필터를 제공한다.

## 시연과 실제 의견

9개 정책의 비용·수혜 규모와 38개 예시 의견은 **합성 시연 자료**다. 실제 통계·공식 견적이 아니다.
지역명 중앙동·푸른동·행복동은 이 앱 안에서 쓰는 예시 명칭이다.
시민 접수 자료는 별도 `is_demo=0`으로 저장하고 시연 자료와 섞지 않는다.
수집하는 시민 입력에는 이름·전화번호·사용자 계정이 없다. 내용은 공개되므로 개인 정보를 적지 않도록 안내한다.
DB 저장 실패를 성공으로 표시하지 않으며, 접수 ID로 중복 요청을 확인한다.

실제 행정기관 전송, 사용자 계정/삭제 관리, 주소 기반 지도, 공식 비용 산정,
학습된 한국어 언어모델 분류는 이번 구현에 포함되지 않는다.
이 앱의 결과는 실제 정책 결정 전에 현장 조사와 주민 논의를 거쳐야 하는 탐구 결과다.
